# PDF Junkie

A local desktop PDF reader for academic papers, built with Electron, React, TypeScript, and Mozilla PDF.js.

Hover over an internal PDF link to read the target in a selectable, scrollable preview. **Ctrl+click** opens that target in a second pane without losing your reading position. Further Ctrl+clicks navigate the opposite pane, from either side. **Cmd+click** also works on macOS.

## Run locally

Requires Node.js **24 or later** and npm. No account, server, or API key is needed.

```sh
npm ci
npm run dev
```

The welcome screen includes a sample paper with bibliography, section, figure, and rotated-page links. Use **Explore with a sample paper** to try the interactions immediately. Open your own PDFs using the file picker, drag-and-drop, a command-line path, or the operating system’s **Open with** action.

To run the production build:

```sh
npm run build
npm start
# Or pass PDF paths directly:
npx electron . /absolute/path/to/paper.pdf
```

On Linux, Electron needs a graphical desktop and the usual Chromium libraries (`libgtk-3-0`, `libnss3`, `libasound2t64`, `libgbm1`). Use your distribution’s Electron/Chromium dependency equivalents if those package names differ. The application retains Electron’s renderer sandbox in normal use.

## Reading

- Internal links preview after 300 ms. Move into the popup to scroll or select text; Escape dismisses it. Its buttons navigate the current pane or the opposite pane. Keyboard focus on an internal link also requests a preview.
- Two panes have independent positions, zoom, rotation, searches, and back/forward histories. Click a pane to make it active. The document sidebar acts on that pane.
- Drag the divider to resize; double-click to reset it. A focused divider accepts arrow keys, with Home restoring an equal split. Toggle the layout to stack the panes vertically.
- Use the sidebar for the document outline or lazy-rendered page thumbnails. Each pane has page and zoom controls. Search includes match counts, previous/next matches, case sensitivity, and highlighting.
- Print prepares every PDF page before opening the native print dialog. Preparation can be cancelled. The reader controls and split layout are excluded from the printed output.
- Light, dark, and system themes change the interface while preserving the PDF’s page colours.

### Shortcuts

| Action                    | Windows / Linux           | macOS                      |
| ------------------------- | ------------------------- | -------------------------- |
| Open PDFs                 | Ctrl+O                    | Cmd+O                      |
| Close tab                 | Ctrl+W                    | Cmd+W                      |
| Find                      | Ctrl+F                    | Cmd+F                      |
| Print                     | Ctrl+P                    | Cmd+P                      |
| Zoom in / out             | Ctrl+Plus / Ctrl+Minus    | Cmd+Plus / Cmd+Minus       |
| Fit width                 | Ctrl+0                    | Cmd+0                      |
| Rotate clockwise          | Ctrl+R                    | Cmd+R                      |
| Toggle split              | Ctrl+Backslash            | Cmd+Backslash              |
| Follow link in other pane | Ctrl+click                | Ctrl+click or Cmd+click    |
| Back / forward            | Alt+Left / Alt+Right      | Option+Left / Option+Right |
| Next / previous tab       | Ctrl+Tab / Ctrl+Shift+Tab | Ctrl+Tab / Ctrl+Shift+Tab  |

Zoom also accepts **Ctrl+=** without Shift and the numeric keypad’s **+ / −** keys.
On macOS, both **Ctrl** and **Cmd** work for these zoom shortcuts.

## Build installers

```sh
npm run dist:linux  # x64 AppImage and .deb
npm run dist:win    # x64 NSIS installer
npm run dist:mac    # Intel and Apple Silicon DMGs
```

Outputs are written to `dist/`. Build on the matching operating system; macOS packaging requires macOS. The included GitHub Actions workflow runs tests and builds each platform’s installers, retaining them as workflow artifacts. It does not publish releases. Packages are unsigned; signing, notarisation, and automatic updates are not configured.

Development package metadata uses the reserved `pdf-junkie.invalid` domain. Replace the homepage and maintainer email in `package.json` with the project’s real details before publishing packages.

## Checks

```sh
npm run typecheck
npm test
npm run test:e2e
npm run test:packaged # after building installers; verifies the packaged reader offline
```

The Electron tests use real PDF.js rendering with generated fixtures: a linked academic-style sample, a 120-page document, a scanned image, invalid input, and a password-protected PDF. Fixtures and the sample are generated by `npm run assets`; the password test uses `read`.

On a headless Linux host, `test:e2e` automatically runs through Xvfb. Install `xvfb` and `xauth` first. Only the automated Linux test launcher uses `--no-sandbox`, because CI/container hosts may disallow Chromium’s sandbox namespaces. Production window settings keep sandboxing enabled.

The tests cover hover previews, source preservation, bidirectional split navigation, search, thumbnails, rotation, lazy rendering, password retry, session restoration, and print output. Test screenshots and failure traces are written under `test-results/`. Physical printer dialogs and OS file-association installation should also be checked manually on each release platform.

## Implementation

`src/main` owns native menus, file registration, scoped document handles, session storage, protocol serving, and desktop operations. `src/preload` exposes a typed bridge with specific operations rather than general IPC or filesystem access. `src/renderer` contains the React interface and adapters around PDF.js’s viewer, link, and find components. Both panes and previews share a loaded document; each full pane owns its own viewer and navigation state.

All rendering assets, including the PDF worker, character maps, standard fonts, ICC profiles, and WASM decoders, are packaged locally. PDF scripting is disabled. External HTTP, HTTPS, and mail links open only after a user click, through the OS.

Reading state is stored in `reader-state.json` in Electron’s platform-specific application-data directory. Open tabs, reading positions, split layouts, theme, and recent files are restored. Closing a tab retains its reading position for the next opening. Passwords and modified PDF contents are never saved. Files are read from their existing location and are not copied into a managed library.

## Current boundaries

Previews follow destinations actually embedded in the PDF. A page-only link previews the page from the top; a broken target reports that it is unavailable. Unlinked citations, scanned-text search/OCR, online paper lookup, annotation editing, cloud sync, and bibliography management are outside this version.
